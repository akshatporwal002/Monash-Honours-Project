## Interpretation

This matrix is the Phase 0 inventory required by
`docs/03-codex-implementation-work-order.md`. It evaluates the current product code at the
baseline commit against the newer controlling requirements. It does not convert an older MVP
traceability claim into proof of the broader LearnLens rule. A row is:

- `IMPLEMENTED` only when current code and a directly relevant automated test prove the whole row.
- `PARTIAL` when useful behaviour exists but a required path, condition, or proof is absent.
- `MISSING` when the required behaviour is not implemented.
- `CONFLICTING` when current behaviour contradicts the controlling specifications.
- `UNVERIFIED` when repository evidence cannot prove the required runtime, human, hosted, or
  measurement claim.

The `Existing proof` column uses the exact evidence keys below. The `Tests` column names current
tests where they prove part of the row and names planned tests or external evidence where they do
not. `NOT RUN` and `UNVERIFIED` are deliberate results, not passes.
