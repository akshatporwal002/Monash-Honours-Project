# Category quality review

FR17 has a reusable review contract for tasks, explanations, suggestions, feedback,
provisional assessments and support representations. Every assessment supplies one
finding for each of the ten FR17 dimensions, an explicit reason, evidence references
and reviewer provenance. Missing, malformed, stale, violated or unverified findings
cannot clear a required review. Review decisions use `APPROVED`/`REJECTED`, separate
from learner results. Deterministic structural checks cannot approve new-content
quality or claim factual accuracy.

`CategoryReviewRequest` binds the complete candidate, category, course, subject,
available evidence and their approvals, and model/prompt/task/policy versions.
`review_output` evaluates an explicitly supplied server-side reviewer;
`require_approved` rechecks the complete receipt binding before use. `review_prompt`
provides the category, exact evidence and response schema to a provider adapter.
The caller must resolve authority and source availability and persist the receipt
within its own output transaction. An unconfigured reviewer rejects; the helper
does not grant publication, evaluator activation or a formal assessment result.

## Educator workflow

For a newly approved generated task, the task review panel loads
`GET /tasks/{task_id}/review/quality`. This protected read returns the exact saved
revision, approved source passages, marking/outcome context and expected review
digest. The educator records a disposition, reason and evidence for every dimension.
Satisfied findings require cited available evidence; a dimension that does not apply
requires an explicit explanation. The server binds the reviewer to the authenticated
course educator and rebuilds the context under the course transaction lock.

Approval and rejection receipts are stored in the protected
`category_quality_reviews` table, with exact task-revision, review-event, course and
reviewer links. The private task history includes these links and findings. Audit
events contain only the digest and identifiers. New generated approvals require the
receipt; existing frozen approval events retain their original policy and history.
Migration `20260911_0054` follows `0053`, creates no approvals and refuses downgrade.

## Suggestions and tutor boundaries

Continuation stores a complete review receipt with each new immutable suggestion.
Its scope is only selection from the current educator-approved curriculum: exact
reviewed task labels and references, prerequisite eligibility and uncertain model
evidence. It explicitly does not remeasure teaching accuracy, accessibility or
learning benefit. No new explanation or assessment decision is generated by this
selection review. Missing/rejected/stale review withholds the suggestion while
preserving learning work and ordinary course access. Historical receipts remain
unchanged, and task availability is checked again when a suggestion is used.

The tutor currently releases only the identical approved hint, with its existing
retained quality checks and transfer restrictions. This delivery does not add a
new generative tutor path. Model-based assessment suggestions and generated support
content use their separately integrated release/approval paths.
