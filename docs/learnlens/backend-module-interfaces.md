# Backend interfaces and independent test entry points

This crosswalk documents all fifteen boundaries required by [Section 8.2 and NFR9](../01-implementation-requirements.md). Each row identifies the caller-facing interface, its responsibility and a test entry point that runs independently of the complete suite. These are logical modules within the MVP application; they do not require separate deployments.

Paths below are relative to `src-main/backend`. HTTP request and response contracts live in `app/schemas`, are exposed by FastAPI's OpenAPI document and are generated into the frontend contract. Service commands and provider protocols remain explicit Python interfaces. A caller must retain the authenticated actor and course/learner scope rather than treating an object identifier as authority.

## Running a module independently

From `src-main/backend`, use the configured virtual environment and select the test entry point required for the changed interface, for example:

```powershell
& ./.venv/Scripts/python.exe -m pytest tests/test_pass_rule_engine.py -q
```

Tests construct their own synthetic fixtures and use local/fake provider boundaries where applicable. A module test is not evidence of production approvals, external provider quality or hosted acceptance. Consult the [current integration receipt](integration-verification-2026-09-11.md) for executed checks and source revisions; this crosswalk documents interfaces and test discovery, not a new test run.
