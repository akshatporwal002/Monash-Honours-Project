## Release procedure supported by the application

`RESEARCH_RELEASE_ENABLED` defaults to `false`. Its environment example remains false. Deployment opt-in alone does not authorize research. The existing `RESEARCH_ENABLED` worker setting and the separate AI evaluator release remain independent controls.

1. A governance custodian records the exact scope and institutional approval, including external evidence, consent/eligibility versions, courses, purposes, fields, named processing researcher, validity windows and each required retention schedule.
2. Authorized authors save the supplied instrument definitions and freeze their content digest. Synthetic definitions remain marked `synthetic_only: true`; a real reviewed version must explicitly be created with `synthetic_only: false`. Freezing a version alone never approves it. The legacy freeze command's `synthetic_review_reference` is a preparation receipt, not institutional authority.
3. The custodian records `instrument_approval` decisions for exact frozen form IDs and digests, with approved state, authority/evidence references and validity windows. The custodian records a `release` decision referencing the exact current institutional approval ID, current plan IDs and instrument approval event IDs. Instrument studies require plans covering all courses in the scope, with approved matching forms for every stage.
4. An authorized deployer enables the deployment opt-in only after the applicable operational checks. Every research operation still requires current participant consent, eligibility and scoped grants as applicable. Research processing and technical-pair export also require the study release; this does not authorize external provider use or pass the separate AI assessment gate.
5. Suspend or revoke the release or instrument approval through new governance decisions. Replacing a scope, institutional approval or current plan invalidates the old release immediately on revalidation. Re-enabling requires current exact bindings; historical records are not rewritten.

The administrator governance-history view exposes receipt IDs for this preparation. Participant and researcher status report the current release rather than a permanent false value. A release can be prepared while the deployment flag is off.

## Reconciliation and export boundaries

`GET /research/instruments/{study}/{course}/study/reconciliation` requires the current study read and instrument read permissions and their exact field grants. It returns pseudonymous allocation/stage status and record references, never raw answers, direct identity or condition. It rejects oversized scans (more than 1,000 study events or observations), rechecks authority before release, and distinguishes `unrecorded`, `response`, `explicit_gap` and `ambiguous` without generating an outcome. Stale, withdrawn, superseded or disposed evidence is excluded with restricted reason counts.

An approved analysis must decide how gaps, corrections, multiple responses and attrition are handled. The reconciliation endpoint is read-only. Existing full-study exports still revalidate exact evidence, authority and operational source lineage while streaming. Delivery of bytes already sent cannot be reversed by a later withdrawal.

## Restricted-text disposal procedure and limits

Administrator-only routes below `/research/governance/{study}/disposal` support `POST /preview` and `POST /execute`. Both enforce authenticated sessions, CSRF and no-store responses. A research export grant does not grant disposal authority.

Preview accepts 1–200 exact instrument response receipt IDs and returns their current restricted-text row IDs/content digests, current scope, supplied retention schedule and a digest of that manifest. It contains no response text and deletes nothing. A custodian must separately record a `disposal_authorization` decision specifying that exact manifest and response list, `record_class: restricted_instrument_evidence`, `method: delete_restricted_text`, a named active administrator executor, external authority/evidence references, `not_before` and `valid_until`. Those dates come from the approved retention decision; elapsed collection time is not treated as disposal permission.

Execution rechecks the current inventory, scope, schedule, hold state, authorization version, executor and window. It creates an immutable minimal `disposal_execution` receipt and deletes the matching restricted-text rows in the same transaction. Exact retries return the receipt. Public governance commands cannot forge an execution decision. Migration `20260911_0053` (parent `20260911_0052`) permits deletion only when the database has a matching execution receipt for the exact row, response and content digest; ordinary deletion remains blocked. The model-generated guard matches the migration. Downgrade reinstates the strict guard and cannot reconstruct deleted content.

The supported deletion class is only `RestrictedInstrumentEvidence.response_text`. Instrument metadata/coded answers, blinded packets and derived research records remain retained, as do all formal assessment, operational source, consent, identity binding and audit histories. No generic deletion path is provided for those classes. If an approved schedule requires their erasure, a class-specific implementation and a resolution of protected-history obligations are still required; this must not be described as a human-only activation step or as complete lifecycle disposal.

Restoring an identical raw row while retaining the execution receipt does not restore research eligibility: direct instrument reads, reviewer packets and operational snapshots reject it. This fixture check is not a complete deployment restore drill. Restoring an older backup without the newer receipt, deleting backup copies, downstream exports, external provider copies and storage-level secure erasure require the approved deployment procedure and independent verification. The application does not claim to erase them. The execution receipt retains only minimum technical identifiers/digests and authorization linkage; it contains no disposed response text.
