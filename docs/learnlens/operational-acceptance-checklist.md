## Final combined drill after integration

The coordinator freezes the combined commit, single migration head/readiness pin,
generated contracts and refreshed validation fingerprints. Reuse recorded passing
baseline checks; repeat affected checks where landed changes invalidate them.

- Run the same built package locally and on the approved host, with configuration
  changes only. Record image digests, frontend/API/worker supervision, every readiness
  check, persistent volume ownership, TLS/cookies and scanner clean/quarantine/error
  behavior. Compose configuration validation alone is not container execution.
- Exercise one authenticated supported/transfer/revision journey through stored
  feedback, model, adaptation and human assessment. Cover the newly integrated
  typed inputs, budget/provider settings, course/source version and scan gates,
  moderation/revalidation decisions, and approved study capture/export boundaries.
- Repeat only invalidated recovery boundaries after new migrations/runtime changes:
  accepted response, feedback claim, assessment job, continuation/outbox and the
  changed study/moderation/source records. Compare exact IDs/counts/digests and
  enforce stale-worker fencing, no duplicate effects and no research resurrection.
  The existing seven-case drill is not rerun merely because this checklist exists.
- Verify the final bundle using retained images and a fresh candidate volume;
  reconcile newer governance records, observe an authorised rollback/cutover, and
  record usable source/result views. No live cutover is performed by this delivery.
- Attach the native/manual/expert/institutional/provider records above. Record
  exceptions explicitly; keep affected activation gates closed until their owners
  supply actual evidence. Readiness, mocks and agent checks are not those approvals.
